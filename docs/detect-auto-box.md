# 自动打框（本地检测模型 → 打码区域）

> 在「图片混淆」页的 V3 面板里加一块**默认折叠**的面板：左侧勾选识别模型（可多选、输出合并），
> 右侧调「识别框扩张」，点一下就把模型框（以及按需把用户手绘的框）填进现有的区域列表。
> **推理全程在浏览器本机进行，图片不上传**；服务端只负责把模型转译成 ONNX 并静态提供。

## 一条数据流看清全貌

```
models/detect/{segm,bbox}/*.pt
      │  服务端启动时（增量、异步、不阻塞 HTTP）
      ▼
tools/detect-export.py  ──►  models/detect/build/<id>.fp32.onnx + <id>.int8.onnx + <id>.json
      │                                   │
      │ /api/detect/models（清单/进度/诊断）  │ /detect-model/*（带缓存的静态路由）
      ▼                                   ▼
src/detect/detect-ui.mjs  ──►  detect-ort.mjs（ORT 会话）──►  detect-core.mjs（纯逻辑解码/合并/扩张/对齐）
      │                                                                     │
      └──────────────►  MOB.addRegion({x,y,w,h})  ◄──────────────────────────┘
                                  │
                                  ▼
                    既有 V3 打码链路（regionEnc + 边框元数据，**未做任何改动**）
```

## 服务端

### 启动期转译（增量，而不是无条件重来）

`server/detect-models.js` 在 `app.listen` **之后**异步启动：扫描 `models/detect/{segm,bbox}/`
下的 `.pt/.pth/.onnx`，凡是「`build/<id>.json` 不存在」或「源文件 sha256 与记录不符」或
「imgsz/opset 变了」的才入队转译（队列并发固定 1，单模型超时 10 分钟）。

为什么不做成"每次启动全部重转"：一个 20 MB 的模型实测要 8~14 秒（导出 + 量化），
全量重转会让每次启动白等几十秒，而结果与上次完全一样。需要强制重转时：
`CX_DETECT_FORCE=1`；想只扫描不转：`CX_DETECT_AUTOCONVERT=0`。

`.onnx` 直接丢进目录也会被采用（拷进 build 并补一份元数据，类别表留空）。

### 接口

| 路由 | 说明 |
|---|---|
| `GET /api/detect/models` | 模型清单（含 `status/classes/files/urls`）+ 转译队列 + python 诊断 + 最近日志 |
| `POST /api/detect/rescan` | 重新扫描并入队（`?force=1` 强制重转） |
| `GET /detect-model/*` | build 产物（`Cache-Control: public, max-age=604800`） |
| `GET /detect-runtime/*` | ONNX Runtime 的 js/wasm（同上） |

> 为什么这两个路由**带缓存**，而 `src/` 是 `no-store`：`src/` 禁缓存是为了防「新页面 + 旧脚本」
> 混搭导致解密失败（见 `server.js` 里的长注释）；而这里是几十 MB 的**不可变二进制**，
> 每次重下毫无意义。两者目的不同，故策略不同。

| 变量 | 默认 | 作用 |
|---|---|---|

| `CX_DETECT_AUTOCONVERT` | `1` | `0` = 不做 `.pt` 转译（需要 python）；**自备 `.onnx` 仍会被直接采用** |
| `CX_DETECT_FORCE` | `0` | `1` = 忽略缓存强制重转 |
| `CX_DETECT_IMGSZ` / `CX_DETECT_OPSET` | `640` / `17` | 导出参数 |
| `CX_DETECT_TIMEOUT_MS` | `600000` | 单模型转译上限 |
| `CX_DETECT_ROOT` | `models/detect` | 模型目录；**部署时可用它指向挂载卷**（镜像里默认没有 `models/`） |
| `CX_DETECT_EXPOSE_DIAG` | `0` | `1` = 接口返回完整的解释器路径与原始日志（默认脱敏，只给 basename） |

### 识别尺度（imgsz）与多尺度构建

ONNX 的输入形状是**导出时写死的静态形状**（`dynamic=False`）：一个文件只能服务一个尺度。
所以"换尺度"只能靠**多份构建**，而多份构建不能共用一个文件名。命名规则：

```
python tools/detect-export.py --src models/detect/segm/ntd11_nsfw_segm.pt --kind segm --imgsz 960
  → models/detect/build/ntd11_nsfw_segm@960.fp32.onnx / .int8.onnx / .json
```

默认尺度 640 保持裸名 —— **已部署的文件名与路由一个字都不变**；非 640 自动加 `@<imgsz>` 后缀。
服务端扫描时把这种"只有构建产物、没有源权重"的条目**直接登记为 ready**（不需要 python：
`.onnx` 已经在 build 里了，就没有任何要跑的东西），所以它天然不受 `CX_DETECT_AUTOCONVERT` 影响。

前端**不再写死 640**（这曾经是个真 bug：按 960 导出后页面仍按 640 送数，ONNX 静态输入不匹配 →
ORT 直接抛错、整个识别失败）。实际采用的尺度按优先级取：

```
ONNX 静态输入形状  >  模型元数据 imgsz  >  640
```

`detect-ort.mjs: staticSize()` 负责这件事。**实测坑**：ORT Web 1.30 里
`sess.inputMetadata` 是数组、条目字段叫 `shape`（不是 typings 里的 `dimensions`），
所以三种形态（`shape` / `dimensions` / `dims`，Map 或普通对象）都认；动态形状（`-1`）返回 0 再由元数据兜底。
"直接采用现成 .onnx"那条路读不出 imgsz（元数据只能填默认值），正是这一层兜住它。

每个模型结果带回**自己那次的 letterbox**，`buildRegions` 按结果里的 letterbox 换算坐标 ——
因此**可以同时勾选 640 与 960**：各跑各自尺度、输出合并，坐标不会算错
（`test/detect/detect-core.test.mjs` 的 T12 守着；两者都没有 letterbox 时直接抛错，
而不是静默按 640 换算）。

面板上「识别尺度」那一行就是这件事的读数（`960px · ntd11_nsfw_segm@960`），模型列表里每个
构建也带 `640px` / `960px` 徽标 —— **换尺度 = 勾哪个构建**。

#### 为什么值得换尺度（实测，同一张 1664×2432 的图）

| 管线 | imgsz | 检出 |
|---|---|---|
| `.pt`（ComfyUI 节点那条路） | 640 | nipples 0.907 / 0.889，**pussy 0.076**（低于任何阈值） |
| `.pt` | 960 | nipples 0.923 / 0.916，**pussy 0.873** |
| `.pt` | 1280 | nipples 0.930 / 0.927，pussy 0.803 |
| 网页 ONNX fp32 + WebGPU | 640 | nipples 0.902 / 0.899，**pussy 无输出** |
| 网页 ONNX fp32 + WebGPU | 960 | nipples 0.924 / 0.914，**pussy 0.873** |

机理：640 下一个 29×55 px 的部位 letterbox 后只剩约 7 px 宽，P3(stride 8) 已分辨不动，
掩膜 proto 又只有输入分辨率的 1/4（640 下 160×160）。

**但不要以为"越高越好"**：8 张测试图批量跑下来，640 单跑漏 4 张、960 单跑漏 2 张
（其中 `19_深喉稳定配方A` 只有 640 能出 `penis 0.936`，960/1280 完全无输出）。
**同时勾多个尺度取并集严格更优，且没有任何多余标签**：

| 配置 | 8 张图合计检出 | 一次点击中位（WebGPU/fp32） |
|---|---|---|
| 640 单跑 | 12 框 | 117 ms |
| 960 单跑 | 16 框 | 168 ms |
| 1280 单跑 | 18 框 | 195 ms |
| 640+960 并集 | 16 框 | 250 ms |
| **640+960+1280 并集** | **19 框** | **315 ms** |

（并集 19 = 1280 的 18 + 1280 检不到、只有 640 能出的那 1 个框。）

**与 `.pt`（ComfyUI 节点那条路）的对标**：同一张图、同一个权重、同样参数下，
逐尺度比对两边检出的类别与框（类别一致且 IoU ≥ 0.5 视为命中）：

| 尺度 | 命中 | 漏 | 多 | 框 IoU 中位 |
|---|---|---|---|---|
| 640 | 12/12 | 0 | 0 | 0.987 |
| 960 | 16/16 | 0 | 0 | 0.983 |
| 1280 | 18/18 | 0 | 0 | **0.996** |

也就是说：**网页（ONNX）与节点（`.pt`）在同一尺度上完全等价** ——
差异从来不在引擎上，只在"看图的尺度"。分数会有 ±0.02 级别的小浮动
（canvas 的缩放滤波与 cv2 不完全相同），类别与框位不受影响。

## 大图分块（半步扫描）

**为什么需要**：ONNX 的输入是 `size×size`（比如 1280）。图比它大时，整图走一遍必须先把图**缩小**，
缩小就意味着小部位掉分（见上表：同一张 1664×2432，整图 640 下该部位 0.076、整图 960 下 0.873）。
超大图（4000×6000 级）缩到 1280 只剩 1/4.7，很多部位会直接低于阈值。

**做法（全部在前端，模型文件与后端接口都不变）**：

1. `planTiles(W, H, { size, overlap: 0.5 })` 把原图切成 `size×size` 的方形窗口，
   **相邻窗口的位移 = size/2**（半步扫描，重叠 50%），末列/末行向内贴 ——
   窗口永远在图内，不产生填充边，右下角那带重叠更多、不会漏掉缝；
2. 每个窗口单独送进模型（`runModel(model, img, { crop: tile })`：canvas 上只画这一块；
   块内坐标靠 `letterbox.crop` 换算回原图 —— 一块局部图就是"这次的原图"，
   与整图路径共用同一套 letterbox/mask 数学）；
3. 所有窗口的候选一起进 `mergeBySource`：IoU > 0.30 或 小框包含率 > 0.80 视为"同一处"，
   只留分最高的那个，并把"这一处被哪几块检出过"记进 `tiles`（面板显示「跨块 ×N」）。

**为什么是半步，而不是刚好铺满**：刚好铺满时，落在接缝上的部位会被两个窗口各切掉一半，
两边都看不全 —— 这正是最常见的漏检来源（这个模型基本靠"完整轮廓"给分）。
重叠 50% 时，任何"最长边 ≤ size/2 的部位"至少能在某一个窗口里**完整出现**；
代价是相邻两块会各检到它一次，由第 3 步合并掉。这条由 `T13` 用像素级全覆盖 +
"任意位置向右半步都有窗口装得下"两条断言守着。

**块数与上限**：块数 = `(ceil((W-size)/step)+1) × (ceil((H-size)/step)+1)`，尺度越小块越多
（同一张 4024×6048：640 → 216 块，1280 → 54 块）。所以**大图要挑大的尺度**。
单张图硬上限 `DEFAULT_OPTS.tileMax = 128` 块：超了直接跳过该模型并在面板提示，不会把浏览器跑死。

**实测（作者那张 1664×2432，conf 0.30，WebGPU/fp32）**：

| 配置 | 块数 | 候选 | 写入区域 | 跨块合并 | nipples | pussy |
|---|---|---|---|---|---|---|
| 640 整图（老路径） | 1 | 2 | 2 | — | 0.902 / 0.899 | **无输出** |
| 1280 整图 | 1 | 3 | 3 | — | 0.929 / 0.927 | 0.803 |
| **1280 + 分块** | 6 | 12 | 3 | 3/3 | **0.955 / 0.951** | **0.873** |
| 640 + 分块 | 35 | 12 | 3 | 3/3 | 0.954 / 0.949 | 0.832 |

分块把同一处的重复检出（候选 12）压回 3 个区域，且三处**都被 4 块各自检到、合并成一处**
（跨块 ×4）：接缝处既没丢也没重。同一张图用 640 分块（35 块 × 41 ms）得到的分数与
1280 分块（6 块 × 139 ms）几乎一样 —— 因为分块后每块都是**原分辨率**，尺度的影响被抹掉大半。

**超大图实测（4024×6048）**：1280 分块 = 54 块、9.2 s、单块中位 119 ms、6 个区域
（其中 1 处是跨 3 块合并的）；同一张图用 640 分块要 216 块 > 上限 128 →
面板提示"换成更大的尺度即可"，不会卡死。

> 前端开关：面板「大图分块」下拉 = 自动（图大于该模型的输入尺度时才切）/ 总是切 / 关闭。
> 描述行里会实时显示"这张图会切几块"（`1280px→6块`），跑完的结论行会写「分块 N 块（重叠 50%，跨块合并 M 处）」。

## 前端

### 面板位置

`src/image-crypto.html` 的 `#pa-v3 > .v3-wrap` **第一个子元素**（正好在
「✏️ 在图上用手指/鼠标框选…」上面）。放在 `#pa-v3` 内意味着只在 V3 模式出现 —— 只有 V3 才有区域。

### 为什么 `src/image-crypto.js` 一行都不用改

| 需要的能力 | 做法 |
|---|---|
| 写区域 | 只用公开方法 `MOB.addRegion()`（它内部会 `norm()`，所以添加后从 `MOB.regions[last]` 取引用） |
| 挂"标签/来源/分数" | `WeakMap`（key = 区域对象）。区域被删/撤销后自动回收，不需要往区域对象里塞字段 |
| 在框上画标签 | 包一层 `MOB.draw`：先调原函数，再画标签（覆盖层坐标系与它一致） |
| 拿到 `MOB/IA/T/$` | `src/detect/deps.js` 显式转交到 `window.__CX_DETECT`；模块不猜全局词法绑定 |

标签/来源/分数**不参与编码**：`IA.metaBytes` 只写 `x,y,w,h`，签名也只由坐标与密码决定，
所以显示怎么改都不会影响解密，也不会破坏与网页端/ComfyUI 移植件的互通（`test/detect` 守着这条）。

### 面板行为

- **默认折叠**，展开状态、模型勾选、参数都存 `localStorage`。
- 展开时才去取 `/api/detect/models`（懒加载，不拖慢首屏）。
- **尺度 = 勾哪个构建**：模型列表每行带 `640px` / `960px` 徽标（该构建的输入边长），
  旁边「识别尺度」那行显示"这次会按什么尺度跑"（`960px · ntd11_nsfw_segm@960`；
  选了多个不同尺度的构建就写 `640px + 960px（各自尺度）`）。一个 ONNX 只能服务一个尺度，
  所以这里不是可调开关，而是"勾哪个构建"的读数 + 怎么加更高尺度的一句话提示。
  前端不写死 640：实际尺度按 `ONNX 静态输入形状 > 元数据 imgsz > 640` 取（见上文那一节）。
- 后端选择自动化：有 WebGPU 就用 `ort.webgpu.min.js` + **fp32**（实测 1152×1920 单帧 42~51 ms），
  否则 WASM + **int8**（10.2 MB、0.66~0.9 s/帧）。列表里显示的就是当前后端会用到的那个变体的体积。
- 扩张：`等比缩放`（绕中心，1.00–2.00×）或 `固定外扩`（0–128 px）；
  `作用对象` 可选「模型框 + 手动框」或「仅模型框」。
- **对齐单元跟随"输出格式"**：PNG(`qv3=100`)→`unit=8`、JPEG(`qv3<100`)→`unit=16`，
  与 `pV3` 的两条路径一致；结论行会写出当前值（`对齐：8px（PNG）`）。
  于是"面板里写的坐标"与"实际打码的像素范围"在两种输出格式下都严格一致。
- **标注**：默认「敏感部位（隐藏类别）」—— 因为实测同一处会被多个类各框一次
  （`pussy`/`anus` 会互相抢位置），类别名不能当功能依据；需要看原始类别名时切到
  「显示模型类别名」，清单与覆盖层会同时改成 `pussy 0.886` 这种写法。
  真实类别名始终保留在元素的 `title` 里（悬停可见），且**从不参与编码**。
- 「⤢ 应用到现有框」把当前参数套到**已有**区域上（含手绘的），并保留一份基准，
  「↺ 还原扩张」可回退（若之后又手动改过框，会要求再点一次确认，避免误清）。
- **大图分块**：下拉选「自动 / 总是切 / 关闭」。自动 = 图比该模型的输入尺度大时切块
  （重叠 50% 的半步扫描，见上文那一节）；描述行会显示预计块数，结论行会写「分块 N 块
  （跨块合并 M 处）」，来源清单里跨块合并过的框标「跨块 ×N」。
- 「🔍 开始自动识别」→ 推理（必要时逐块）→ 跨模型/跨块合并 → 扩张 → 8 像素对齐 → 写入区域
  （上限 12 个，超出按分数取舍并提示）。

## 原项目"标记框"参数检索结果（自动打框必须服从的口径）

| 参数 | 值 / 出处 | 为什么自动打框要在意 |
|---|---|---|
| 区域数上限 | **12**（`MOB.addRegion`；`IA.parseMeta` 里 `cnt>12 → null`） | 超了就打不进元数据、**解不回来**。所以合并后必须 ≤12 |
| 坐标钳制 | `MOB.norm()`：钳进图内并取整 | 扩张后要重新钳制 |
| 最小框 | 手绘 `w>8 && h>8` | 自动框同标准（对齐后不足 8px 的丢弃） |
| 整块对齐 | `pV3`：`x/y` 向下取整到 `unit`，`w/h` 回落完整块；`unit=8`（PNG）/`16`（JPEG） | 标签里显示的必须是**对齐后**的值，否则"列表写的"和"实际打的"不一致 |
| 边框 | `B=8`（PNG）/ `64`（JPEG J2 码） | 区域用**原图**坐标，边框由 pV3 外扩，自动框不用管 |
| 元数据容量 | `rMetaPng(..., maxB=200)`，每区域 8 B | 与 12 上限互相印证 |
| 密码/顺序 | 单密码，`seed=hash(k+'#'+idx)`；加密正序、解密逆序 | 自动框只做**追加**，不重排既有区域 |
| 标签是否入编码 | **不入**（只写 x/y/w/h） | 所以"标明部位"是纯展示，不影响兼容性 |

**"标明"的落地**：面板里每个区域显示 `掩膜外接框/检测框 · 类别 置信度 · 来源模型`，
覆盖层上画小标签；多模型命中同一处时显示 `来源A+来源B`。
类别名**仅供参考** —— 实测同一处会被多个类各框一次（`pussy`/`anus` 会互相抢位置），
所以默认按「敏感部位」合并，不按类别分级。

## 上云部署影响（三种交付形态 + 一条硬约束）

先说清楚：这个项目**不是纯前端**——README 的「生产 Web 版」是 `src/` + `server/server.js` + `deploy/`
（后端提供静态托管与 PKI API）；作者的"纯前端"指的应是**加密/解密全在浏览器、服务器不接触明文与私钥**。
本功能遵守同一条线：**推理也在浏览器本机，服务器只多了一个静态目录 + 4 个只读路由**。

| 交付形态 | 影响 | 说明 |
|---|---|---|
| 静态托管（GitHub Pages / CDN / 对象存储） | **零影响** | `src/detect/*` 会随 `src/` 一起发布；`/api/detect/models` 404 → 面板经 `StaticHost` 判断显示"静态托管下不可用"。运行时（`src/vendor/ort/`，gitignore）与权重本来就不在产物里。也不影响单文件版与隐写等其它信道 |
| Docker / 自托管（`deploy/`） | **零新增依赖**，需注意两点 | ① 镜像只 `COPY server/ src/`，所以镜像里**没有 `models/` 也没有 python** → `available:false`，面板显示原因，站点其余功能照常；② 想在容器里用：挂一个卷放模型（`-v .../detect:/app/models/detect` 并配 `CX_DETECT_ROOT`），镜像内再装 python 侧依赖（torch/ultralytics/onnxruntime，体积较大，按需自行决定） |
| 单文件版 `single-file/` | **零影响** | 它没有服务端与多文件路由；面板只存在于 `src/image-crypto.html` |

**"后端零模型代码"形态（可选，正对着"转译算不算后端计算"这个疑问）**：
`CX_DETECT_AUTOCONVERT=0` + 自备 `.onnx`（在本机用 `tools/detect-export.py` 导出后丢进
`models/detect/segm|bbox/`）→ 服务端只做**文件拷贝 + 静态分发**，不装 python、不 spawn 任何
模型进程。实测该形态下（python 依赖缺失）模型仍被正常采用并可被浏览器取用。
也就是说：**转译是可选的准备工作，不是运行时的必经环节**；推理始终在浏览器里。

**硬约束：可选功能绝不能带崩服务。** `detect-models.start()` 跑在 `app.listen` 之后的异步流程里，
而 Node 16+ 会把**未捕获的 promise rejection 直接当致命错误退出进程**。所以：

- 建目录、扫描、转译全部包在 try/catch 里，失败只 warning + 降级（`available:false` + 可执行 hint）；
- 目录不可写时直接停手（不再做任何 FS 操作），并支持 `CX_DETECT_ROOT` 改指可写目录/挂载卷；
- 实测（把 `CX_DETECT_ROOT` 指向一个普通文件制造 `ENOTDIR`）：站点 `GET /image-crypto.html` 仍 200、
  `/api/detect/models` 返回 `available:false` 且 hint 写明 `ENOTDIR: not a directory, mkdir ...`、
  进程存活可继续服务；修复前这个场景会把整个 Node 进程带走。

**首屏字节**：`detect-ort.mjs`（连同 ORT 运行时）改成**展开面板 / 点识别时**才 `await import()`，
所以静态托管下每个访客首屏只多 `deps.js`(1KB) + `detect-core.mjs`（纯数学，约 10KB，gzip 后 3~4KB）。

**公网部署的两点提醒**（不阻塞合并，交给部署者判断）：

1. `/api/detect/models` 默认**已脱敏**（解释器只回 basename、日志与目录抹掉绝对路径）；
   需要排查时开 `CX_DETECT_EXPOSE_DIAG=1`。
2. `/api/detect/rescan` 是**无鉴权的 POST**：它只做"扫描 + 对未转译的模型入队"，
   没有模型文件变动时既不会重复转译、开销也只是一次 sha256；但如果站点暴露在公网，
   建议在反代层对它限速，或加一个 `CX_DETECT_ENABLE_RESCAN=0` 之类的开关（当前未实现，按需再加）。

## 降级与边界

| 情况 | 行为 |
|---|---|
| 静态托管（GitHub Pages）/ 单文件版 | 面板显示"不可用 + 原因"，不报错，加密解密照常；单文件版不含本功能（8 信道合并产物保持原样） |
| 没装 python / 缺 torch·ultralytics | `/api/detect/models` 返回 `available:false` 与 `hint`（提示可用 ComfyUI 的 venv），面板显示原因 |
| 没放模型 | 面板提示目录位置，并给「重新扫描」按钮 |
| 某模型转译失败 | 该模型标 `error`（悬停看 stderr 摘要），其余模型照常可用 |
| 干净图零检出 | 不添加任何区域，只提示"未检出"，不动用户已有的框 |
| 合并后超过 12 个 | 按「按分数」策略截断并提示，不静默丢弃 |
| 无 WebGPU | 自动退 WASM + int8，面板显示当前后端 |
